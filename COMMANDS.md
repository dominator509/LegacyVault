# Commands

Export `CI=true GIT_TERMINAL_PROMPT=0 GIT_PAGER=cat PAGER=cat DEBIAN_FRONTEND=noninteractive`. Legal commands are `sh scripts/install.sh`, `preflight.sh`, `lint.sh`, `format-check.sh`, `typecheck.sh`, `test-unit.sh`, `test-integration.sh`, `test-e2e.sh`, `contract-test.sh`, `build.sh`, `security-check.sh`, `dependency-audit.sh`, `smoke-test.sh`, `live-fire.sh`, `stripe-live-fire.sh`, `verify.sh`, and `production-readiness-check.sh`. `sh scripts/contract-test.sh` starts a bounded local API and runs isolated pinned Schemathesis 4.24.3 coverage and deterministic fuzzing against its OpenAPI document, then tears the API down. `sh scripts/live-fire.sh` also starts a bounded local API and runs the official Grafana k6 2.0.0 container pinned to digest `sha256:a33a0cfdc4d2483d6b7a3a22e726a499ff2831a671a49239104cd34a9937523c` against 50 concurrent authenticated sessions; it owns and tears down that API process. Local API start: `pnpm --filter @legacy/api start >.agent/state/api.log 2>&1 & echo $! >.agent/state/api.pid`; local worker start: `pnpm --filter @legacy/worker start >.agent/state/worker.log 2>&1 & echo $! >.agent/state/worker.pid`; probe the API with curl and stop each process using its PID file. Adapter parity: `for f in AGENTS.md CLAUDE.md HERMES.md OPENCLAW.md; do awk '/PRIME-BLOCK-BEGIN/,/PRIME-BLOCK-END/' "$f" | cksum; done`.

Local backup proof uses `sh scripts/local-backup.sh`. The corresponding non-production restore rehearsal uses `sh scripts/local-restore-drill.sh` with the newest ignored backup or `sh scripts/local-restore-drill.sh .agent/state/backups/<exact-file>.dump`. The restore script accepts only its validated `legacy-vault-*.dump` path and creates/drops only a validated temporary `legacy_restore_*` database inside the local Compose PostgreSQL service. These commands never target Neon or production.

EP-009 image rehearsal uses `docker build --target api -t legacy-vault-api:local .`, `docker build --target web -t legacy-vault-web:local .`, `docker build --target worker -t legacy-vault-worker:local .`, and `docker build --target release -t legacy-vault:local .`. These local tags are never release evidence. `sh scripts/local-release-rehearsal.sh` starts the combined local image on ports 13000/13001 against the approved Compose network, proves the real web and API processes, and always removes only its fixed rehearsal container. Authenticated staging validation uses `sh scripts/staging-smoke.sh https://<exact-named-staging-app>` and `sh scripts/staging-live-fire.sh https://<exact-named-staging-app>`. Production remains manual and uses the exact command in `DEPLOYMENT.md`; local agents must not execute it.
`sh scripts/local-migration-rehearsal.sh` proves idempotent local migrations, then creates, verifies, restores, compares, and cleans a real PostgreSQL backup. It never targets an external database.

`sh scripts/stripe-live-fire.sh` requires only ignored Stripe test-mode configuration. It creates one synthetic subscription Checkout Session through the production adapter, retrieves and verifies its tenant metadata and exact Price through the real Stripe API, and expires it in the same bounded test. It also creates a metadata-marked synthetic customer, proves the production billing-portal adapter, and deletes that customer in the same bounded test. It never completes payment, creates customer vault data, or treats the session as a successful subscription.

EP-009 workflow action refs may be resolved read-only from their authoritative repositories with `git ls-remote https://github.com/<owner>/<action>.git <exact-tag-or-branch-ref>` before recording an immutable commit SHA. This command does not install code or mutate an external repository.

The release workflow may run `node scripts/materialize-ci-env.mjs` only when GitHub Actions sets both `CI=true` and `GITHUB_ACTIONS=true`; it overlays the explicit external allowlist onto an already generated ignored local environment without printing values. Local agents must not invoke it against their `.env`.

Bootstrap diagnostics authorized by ADR-010: `git --version`, `node --version`, `corepack --version`, `pnpm --version`, `docker version`, `docker compose version`, and `df -h .`. When the installed Docker Desktop engine is stopped, start `C:\Program Files\Docker\Docker\Docker Desktop.exe` with PowerShell `Start-Process -WindowStyle Hidden`, then run `docker version` at most 30 times with two-second intervals. Windows bind failures may be diagnosed read-only with `netsh interface ipv4 show excludedportrange protocol=tcp`. Dependency metadata may be inspected without mutation using `pnpm view <package> version`. `sh scripts/install.sh` creates the first lockfile only when it is absent and requires `--frozen-lockfile` on every subsequent install. Local environment generation uses `sh scripts/generate-local-env.sh`; `sh scripts/generate-local-env.sh --rotate` is allowed only for development-secret rotation. Existing ignored local files with legacy crypto formats can be narrowly repaired without rotating service credentials using `sh scripts/repair-local-export-key.sh` and `sh scripts/repair-local-encryption-key.sh`. The real local dependency stack uses `docker compose up -d --wait`, `docker compose ps`, and `docker compose down`; destructive volume removal is not an ordinary command. Database migrations use `pnpm db:migrate` after readiness. CI browser setup uses the pinned workspace CLI through `pnpm exec playwright install --with-deps chromium`; local Chrome remains the preferred already-installed browser when available. Implementation formatting uses `pnpm exec prettier --write apps packages tests package.json pnpm-workspace.yaml tsconfig.json tsconfig.build.json compose.yaml scripts/security-check.mjs scripts/run-release-stack.mjs scripts/materialize-ci-env.mjs scripts/probes/redis_url.mjs`; the immutable blueprint/control prose and generated lockfile are excluded by `.prettierignore`. Coding agents must not invent commands. If a command is missing or stale, update this file first, citing repository evidence, with a Decision Log entry.

After the real local dependency stack is ready, `pnpm exec tsx scripts/bootstrap-local-storage.ts` idempotently creates the configured loopback-only development bucket. The command rejects non-local endpoints and non-engineering environments. Credential-free CI may then pre-pull the immutable OCR runtime with `docker pull jbarlow83/ocrmypdf:v17.8.1@sha256:0563a68359fe4e68022974103794a69d5d37270686f99c9030a7667ebbb639d4` before integration tests. This prevents a first-use image download from consuming an OCR process timeout and does not authenticate to or mutate a provider.

After an evidence-backed exact dependency or workspace manifest change, refresh the lockfile once with `pnpm install --no-frozen-lockfile`, then immediately prove determinism with `sh scripts/install.sh` and run `sh scripts/dependency-audit.sh`.

Better Auth schema SQL is compiled read-only from the installed, pinned provider API with `pnpm --filter @legacy/auth schema:compile`; review the output before transcribing it into a numbered migration. Do not run provider-generated migrations directly against production.
